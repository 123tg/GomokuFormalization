# 搜索器方法详解(5 分钟讲稿)

> 项目:Gomoku Formalization — 7×7 五子棋,五连即胜,黑先
> 讲稿约 800 字,语速正常约 5 分钟。

---

## 开场(30 秒)

大家好。这个项目的搜索器是 C++ 写的,只做一件事:**找证明的候选**。它找出来的东西不算数,最后由 Lean 检查器逐节点重算,通过才是定理。今天讲搜索器内部的核心方法,一共四点:DFPN、VCF、威胁排序、强制剪枝。

## 1. 总览(30 秒)

搜索器有两种模式。模式 A 叫强制胜搜索,证明"黑棋(或白棋)能强制获胜";模式 B 叫防守证明,证明"防守方能阻止对方获胜"。两条流水线共用同一套局面表示和着法排序。今天重点讲模式 A 的搜索策略。

## 2. DFPN 证明数搜索(2 分钟)

模式 A 的主搜索是 DFPN,全称是"深度优先证明数搜索"。

它的核心思想是:给每个节点维护两个数。第一个叫**证明数 pn**,意思是"证明这个局面是必胜,还需要展开多少个叶子";第二个叫**反证数 dn**,意思是"证明这个局面不是必胜,还需要展开多少个叶子"。pn 越小,越接近证明;dn 越小,越接近推翻。

这两个数怎么算?看节点类型。**目标方回合是 OR 节点**——我只要有一个着法能赢就行,所以证明数取所有孩子的最小值,反证数求和。**对手回合是 AND 节点**——我必须应付每一个应手,所以证明数求和,反证数取最小值。一句话:**OR 取小、AND 求和,反过来对称**。

有了这两个数,搜索策略就很简单:每一轮,沿着 pn 或 dn 最小的孩子一路深入,同时传一个**阈值**——如果这个孩子已经比第二好的孩子还差,再深入它没有意义,就换分支。子节点返回后,更新父节点的 pn/dn,继续循环。

举个例子:根节点有 A、B、C 三个孩子,pn 分别是 2、5、9。DFPN 先深入 A;如果 A 证明必胜,根的 pn 归零,整个证明完成,B 和 C 根本不用展开。如果 A 被推翻,再选 B。这样,预算自然流向最能闭合证明的分支,而不是盲目遍历整棵树。

为什么用 DFPN?因为它深度优先、内存小,而且 pn 直接度量"离证明还有多远",特别适合证明问题。但要注意:pn/dn 只是估计,剪枝和缓存都不可信,只影响速度。

## 3. VCF 连续冲四(1 分钟)

VCF 是五子棋特有的杀棋检测,全称"连续冲四"。

**冲四**就是:下一子就能成五,对手必须立刻堵。VCF 的思路是:我不断冲四,对手被迫防守,直到成五。

算法很简单:先找一步成五,找到直接赢;否则试每个着法,落子后看形成了几个成五威胁。如果形成**两个**威胁,就是双冲四——对手一步只能堵一个,必输,直接判定杀棋;如果只有一个威胁,对手被迫堵住,然后递归继续,一次攻防算两步。

VCF 找到的杀棋首着会作为"提示"传给 DFPN,让主搜索先试杀棋。攻不下来就退回通用搜索。

## 4. 威胁排序与强制剪枝(1 分钟)

最后是排序和剪枝。展开节点前,先给每个候选着法打分:能成五的加一百万,能堵对方成五的加五十万,剩下的按"邻域分"排——挨着已有棋子、靠近中心的好。

排序之外还有**强制剪枝**:在目标方回合,如果存在成五着法,只搜成五;如果没有成五但有防守着法,只搜防守。直觉很简单:对方都冲四了,你不去堵就是送死,其他着法不可能更好。

有人会问:剪枝会不会把真证明剪掉?不会。第一,剪枝只发生在目标方回合——反正我选一个能赢的着法就行,必胜首着一定在保留集合里;第二,对手回合从不剪枝,应手全部展开;第三,证书导出时,攻击方节点仍然列出全部合法应手,Lean 检查器验证"全应手覆盖",漏一个就整张被拒。

## 收尾(30 秒)

总结一下:DFPN 用 pn/dn 指导搜索往哪深入,VCF 快速识别杀棋,威胁排序和强制剪枝把预算花在刀刃上。但记住一句话:**搜索器可以犯错,检查器不放错;通过检查的证书,才是定理。** 谢谢大家。

## 1. 总览

搜索器是 C++17 写的可执行文件 `gomoku_solver`,内部有两条搜索流水线,共用同一套局面表示、着法排序和剪枝基础设施:

| | 模式 A:强制胜搜索 | 模式 B:防守证明搜索 |
|---|---|---|
| 类 | `DfpnSolver` | `DefenseSearcher` |
| 目标 | 证明"某方能强制获胜" | 证明"防守方能阻止对方获胜" |
| 语义 | `CanForceWin` | `CanPreventWin` |
| 输出 | `CompactCertificate` | `DefenseCertificate` |
| 命令行 | `--input ...` | `--prove prevent-black-win \| prevent-white-win` |
| 主搜索 | **DFPN + VCF 快攻** | 完整 AND/OR 深度优先 |

**贯穿全局的设计纪律**:两条流水线产出的都只是**候选数据(certificate)**——任何算法、启发式、缓存、剪枝都不能直接当结论,最终由 Lean 检查器逐节点重算,通过才是定理。

本讲稿聚焦模式 A 的搜索策略(DFPN、VCF、排序、剪枝),因为这些方法体现了"如何把有限预算花在刀刃上"的全部思想;模式 B 的 AND/OR 搜索是更朴素的完整枚举,不再展开。

## 2. DFPN 证明数搜索(核心)

### 2.1 一句话

DFPN(Depth-First Proof-Number Search,深度优先证明数搜索)给每个节点维护两个数——**证明数 pn** 和**反证数 dn**——用它们估计"离证明还有多远",然后反复深入最有希望的分支,把搜索预算集中在最可能出结果的地方。

### 2.2 两个数:pn 与 dn

对"目标方(target)能否强制获胜"这个问题,每个局面节点记录:

- **证明数 pn(proof number)**  
  证明"该局面是目标方必胜"至少还需要展开多少个叶子节点(下界)。
  - pn = 0:已经证明必胜;
  - pn 越大:离证明越远,越不值得优先投入。
- **反证数 dn(disproof number)**  
  证明"该局面不是目标方必胜"(即对手能防住或和棋)至少还需要展开多少个叶子节点(下界)。
  - dn = 0:已经证明非必胜;
  - dn 越大:越难推翻。

代码:`cpp/src/gomoku_solver.cpp` 中 `struct Entry { proof, disproof, expanded, moves }`,初始值 pn = dn = 1(未知局面至少还要展开 1 个叶子),上限 `infinity = 1<<30`。

### 2.3 pn/dn 的计算规则(为什么这样算)

见 `recompute`:

**目标方回合 = OR 节点**(我方选一个着法,有一个能赢就行):

```
pn = min(所有子节点 pn)     -- 只要有一个孩子接近证明,我就选它
dn = Σ(所有子节点 dn)       -- 要证明我赢不了,必须所有孩子都赢不了
```

**对手回合 = AND 节点**(对手选应手,我必须全部应付):

```
pn = Σ(所有子节点 pn)       -- 我要赢,必须赢过每一个应手
dn = min(所有子节点 dn)     -- 对手只要有一个应手能防住我,我就赢不了
```

直觉:
- OR 节点是"存在"语义 → 证明数取最小(找最弱环节),反证数求和(推翻全部才推翻);
- AND 节点是"全称"语义 → 证明数求和(全部打通才证明),反证数取最小(一个破绽就推翻)。

**终局赋值**(`ensureEntry`):
- 目标方已获胜 → pn = 0,dn = ∞(已证明,无法推翻);
- 目标方已失败/和棋 → pn = ∞,dn = 0(已推翻,无法证明);
- 深度耗尽(迭代加深的边界)→ 按"本次查询内不可证明"处理:pn = ∞,dn = 0。

### 2.4 展开(expand):把节点变成一棵小树

`expand` 做三件事:
1. 生成**排序后的着法列表**(见第 4 节:成五 > 防守 > 邻域分);
2. 对每个着法 `play` 出子局面并建表项(浅层子节点先不展开);
3. 用子节点初值 `recompute` 父节点的 pn/dn。

注意:expand 只建一层,子节点的 pn/dn 一开始都是 1(或终局值),随着搜索深入才被精化。这就是"迭代展开"的思想——树是**按需生长**的,不是一次性建好。

### 2.5 选择策略:永远深入"最需要证明"的孩子

`dfpn(position, depth, proofThreshold, disproofThreshold)` 的主循环:

1. 取当前节点的 pn、dn;
2. 若 `pn == 0`(已证明)或 `dn == 0`(已推翻)或达到阈值 → 返回;
3. 否则遍历所有孩子,对目标方回合按 **pn 最小**、对手回合按 **dn 最小** 选出 `bestIndex`,同时记录**第二小**的值 `secondValue`:
   - 目标方回合:我优先深入"最容易证明我赢"的孩子(pn 最小);
   - 对手回合:我优先深入"最容易证明我输"的孩子(dn 最小)。
4. 递归 `dfpn(selected, depth-1, 子阈值)`:
   - 目标方回合:子 pn 阈值 = min(父阈值, secondValue + 1)——如果这个孩子已经比第二好的孩子更差,再深入它没有意义;子 dn 阈值 = 父 dn − 当前 dn + 孩子 dn。
   - 对手回合:对称。
   这就是 DFPN 的**阈值传递**:每个孩子只被深入"到它可能改变父节点结论为止"。
5. 子节点返回后,如果它的 pn/dn **没有变化**,说明阈值内推不动,整条线到此为止;否则 `recompute` 父节点,继续循环。

### 2.6 完整流程(与迭代加深配合)

`solve` 入口:
```
for depth = 1 .. maxDepth:
    dfpn(root, depth, ∞, ∞)
    if root.pn == 0: 找到证明 → 导出证书
```
每一层都是一次完整的 DFPN 求解;浅层失败(返回 depth-limit)后加深重来,深层的置换表能复用浅层结果。

### 2.7 一个小例子(理解 pn/dn 怎么指导搜索)

假设目标方回合,根节点有 3 个孩子 A、B、C,各自 pn = 2、5、9:

```
        根 (OR)          pn = min(2,5,9) = 2   dn = Σ = ...
       /    |    \
      A     B     C
   pn=2   pn=5   pn=9
```

- DFPN 选择深入 A(pn 最小);
- A 被证明必胜后,根 pn 归 0 → 整个证明完成,B、C 根本不用展开!
- 若 A 被证明非必胜(pn → ∞),根重新选 B 继续;
- 若 B、C 的 dn 总和超过根阈值,搜索也会提前终止——**阈值避免了无谓的全面展开**。

这正是 DFPN 比普通 Alpha-Beta 更适合"证明问题"的原因:**pn 直接度量"离证明还有多远"**,预算自然流向能最快闭合证明的分支。

### 2.8 为什么用 DFPN(取舍)

- ✅ 深度优先:内存占用小(只有一条路径的栈 + 置换表);
- ✅ 证明导向:pn/dn 是证明问题的天然启发,不依赖局面估值;
- ✅ 阈值剪枝:避免了"所有分支都展开"的指数爆炸;
- ⚠️ 代价:pn/dn 是**估计**,启发不完美时可能反复横跳;
- ⚠️ 不可信:pn/dn、剪枝、缓存全部只影响搜索效率,证明由 Lean 重算。

## 3. VCF 连续冲四快攻

### 3.1 一句话

VCF(Victory by Continuous Four)是五子棋特有的杀棋检测:我方不断冲四、对手被迫防守,直到成五——在"杀棋形态"明显的局面上,比 DFPN 通用搜索快几个数量级。

### 3.2 冲四是什么

**冲四**:下一子就能成五的着法。对手**必须立刻堵住**,否则下一手成五获胜。代码用 `createsFive(move, player)` 判定:在该点落子后,player 是否形成 ≥5 连。

相关概念(代码 `winningMoves`):
- **一步成五**:落子即成五,直接赢;
- **冲四**:落子后形成"再一子就五"的威胁;
- **双冲四**:落子后同时形成两个独立的成五威胁——对手一步只能堵一个,必输。

### 3.3 算法流程(逐步)

`probeVcf(position, remaining)`,返回"杀棋首着"或空:

```
1) 查 VCF 置换表 → 命中直接返回
2) 若 remaining == 0 或 不是目标方回合 或 已终局 → 返回空
3) 直接找一步成五:createsFive(move, target) → 找到即返回该 move
4) 对每个候选着法 move(按邻域分排序):
     a. 模拟目标方落子 → afterAttack
     b. 若 afterAttack 已终局:
          目标方赢 → 返回 move;否则跳过
     c. 计算 targetThreats = 目标方在 afterAttack 的成五着法集合
        - 若为空:这次进攻没造成威胁,跳过
        - 若对手也有成五着法:这步进攻无效(对手先赢了),跳过
        - 若 targetThreats.size() >= 2:双冲四!返回 move
        - 若只有一个威胁:
            d. 对手被迫堵住(唯一应手)
            e. 若堵完终局 → 跳过
            f. 递归 probeVcf(堵后局面, remaining-2)   ← 一攻一防两步
               返回非空 → 整条杀棋成立,返回 move
5) 全部试完 → 返回空(这条线没有 VCF 杀棋)
```

注意 `remaining-2`:VCF 里一次"进攻+被迫防守"算两 ply,预算按对子消耗。

### 3.4 双冲四为什么是杀棋

对手一回合只能落一子,而双冲四同时产生**两个**成五威胁:
```
  例:黑方落子 X 后,横线"黑黑黑_X"成五、竖线"黑黑黑_X"也成五
      白方堵横线 → 黑下竖线成五;堵竖线 → 黑下横线成五
```
所以代码里 `targetThreats.size() >= 2` 直接判定杀棋,不再递归。

### 3.5 与 DFPN 的配合

- **独立预算**:`maxVcfNodes` / `maxVcfDepth`,与 DFPN 的 `maxNodes` 互不干扰;
- **着法提示(vcfHints)**:VCF 找到的杀棋首着会被记入 `vcfHints`,DFPN 在目标方回合把该着法 `std::rotate` 到候选列表第一位——先试杀棋,不行再回通用搜索;
- **失败即退回**:VCF 是"快攻",攻不下来就继续 DFPN 全局面搜索,不影响正确性。

### 3.6 例子(理解递归)

```
黑方回合,目标 = 黑。局面:横线 黑黑黑_ _
VCF 流程:
  move = (补第四子) → 黑方形成冲四
  targetThreats = {成五点} (1 个威胁)
  白方被迫堵 → 堵后局面
  递归 probeVcf(堵后, remaining-2):
      黑方再冲四 → 白方再堵 → ……
      直到某一步黑方直接成五 → 返回首着
```
整条链返回后,DFPN 得到提示:第一步先冲四。

### 3.7 为什么有用

- **攻击端**:大多数五子棋杀棋是连续冲四形态,VCF 一步到位;
- **防守端**:被冲四时对手合法应手骤减到 1 个,AND 分支从几十降到 1;
- 但 VCF 只覆盖"冲四杀棋"这一种模式,不是通用证明——所以它永远是**加速器**,不是证明本身。

## 4. 威胁排序与强制防守剪枝

### 4.1 一句话

在展开任何节点前,先把候选着法按"威胁从高到低"排序,并在目标方回合用"有成五只搜成五、有防守只搜防守"的强制剪枝砍掉明显不可能的分支——只影响速度,不影响正确性。

### 4.2 着法打分(见 `orderedMoves` / `sortedEmptyMoves`)

对每个空格 `move`,计算:

```
score = neighborhoodScore(move)          -- 邻域启发分(见下)
if createsFive(move, 当前方):   score += 1,000,000   -- 成五:立即获胜
if createsFive(move, 对方):     score +=   500,000   -- 防守:堵住对方成五
```

排序:分数从高到低;同分按 y、再按 x,保证**可复现**(同样输入永远同样顺序)。

**neighborhoodScore**(`cpp` 第 173 行):
```
对 move 的 5×5 邻域内每个棋子:
    相邻 8 格(切比雪夫距离 ≤1):+8
    其余 16 格(距离 2):+2
减去 |x−3| + |y−3|(到棋盘中心的曼哈顿距离)
```
直觉:五子棋的好点通常挨着已有棋子(有发展空间),且靠近中心(四方向都能延伸)。它只是排序启发,与证明无关。

### 4.3 强制防守剪枝(Forced-Move Pruning)

目标方回合(prover)且开启 `forcedMovePruning` 时:

```
hasWinning  = 存在成五着法
hasDefense  = 存在防守着法(不成五但能堵对方成五)

if hasWinning:  只保留成五着法,其余全部跳过
elif hasDefense: 只保留防守着法,其余全部跳过
```

直觉:对方已经形成冲四/活四,你不去堵就是送死——**任何非防守着法都不可能比防守着法更好**,可以安全剪掉。这能把 OR 分支从几十个砍到 1~2 个。

相关参数:
- `--no-forced-pruning`:关闭该剪枝(对照实验用);
- `--max-prover-moves N`:目标方回合最多保留 N 个候选(选择性宽度,0 = 完整)——又一个预算旋钮,同样只影响搜索。

### 4.4 为什么剪枝不破坏证明完整性(关键!)

- 剪枝只作用于**目标方回合**(prover),即 OR 节点——目标方"选一个能赢的着法即可",砍掉非成五/非防守着法是**安全的**:如果存在必胜策略,必胜首着必然在保留集合里;
- **对手回合(AND 节点)从不剪枝**:攻击方应手必须**全部**展开;
- 更重要的:**证书导出时**,`emitProof` 对攻击方节点仍然列出全部合法应手(模式 A 的 `opponentMoves`、模式 B 的 `attackerMoves`),Lean 检查器验证"全应手覆盖",漏一个就整张被拒。

所以:剪枝加速搜索,但**证明的完整性由导出阶段 + Lean 检查器兜底**,剪枝永远不可能把假证明变真。

### 4.5 例子

```
黑方(目标)回合,局面:白方已有 冲四_ _ (白下一子就五)
候选着法排序:
    A: 堵白方成五点      score = 邻域分 + 500,000   ← 防守
    B: 远处发展黑棋      score = 邻域分              ← 非防守
    C: 黑方一步成五      score = 邻域分 + 1,000,000 ← 成五(若有)

强制剪枝逻辑:
    hasWinning = 是否有 C → 有:只搜 C(直接赢)
    hasWinning = 无, hasDefense = 有 → 只搜 A(必须堵)
    B 永远不会被展开 —— 但 B 也绝不可能更好,剪掉安全
```

## 附:与 Lean 验证的关系(收尾一句话)

> 搜索器可以犯错,检查器不放错;通过检查的证书才是定理。
> DFPN 的 pn/dn、VCF 杀棋、威胁排序、强制剪枝、Zobrist、置换表、各种预算——全部只影响"找候选"的速度;证明由 Lean 逐节点重算 + soundness 定理保证。
